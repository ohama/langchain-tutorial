# LCEL RAG 체인

## 개념: 왜 필요한가

검색만으로는 조각 목록이 나올 뿐, 답이 나오지 않는다. RAG(Retrieval-Augmented Generation)는 검색으로 찾은 조각을 프롬프트의 컨텍스트로 넣어, LLM이 그 내용을 근거로 답하게 만드는 기법이다. 이렇게 하면 모델이 한 번도 학습하지 않은 내용 — 이 책의 가상 사내 근무 규정 같은 — 에 대해서도 답할 수 있다.

프롬프트에 "문서에 답이 없으면 '문서에서 찾을 수 없습니다'라고 답하세요"라는 지시를 넣으면 근거 없는 답변을 줄일 수 있지만, 완전히 없애 주지는 않는다 — 모델이 지시를 따르는지는 매번 실제 출력으로 확인해야 한다.

이 흐름 전체는 1부 4장에서 다룬 LCEL 파이프 하나로 표현된다. 딕셔너리를 파이프에 넣으면 `RunnableParallel`이 되어 같은 입력이 여러 갈래로 동시에 흘러가고, `retriever | format_docs`는 검색된 문서 여러 개를 문자열 하나로 합치며, `RunnablePassthrough`는 질문 문자열을 그대로 다음 단계로 흘려보낸다.

### 예제 코드

`examples/ch03_rag/03_rag_chain.py`

```python
{{#include ../../../examples/ch03_rag/03_rag_chain.py}}
```

- retriever는 `vectorstore.as_retriever(search_kwargs={"k": 2})`로 만든다 — 항상 가장 가까운 `k`개를 돌려준다.
- `format_docs`는 검색된 `Document` 리스트를 `\n\n`으로 이어 붙여 프롬프트에 넣을 문자열 하나로 만든다.
- 프롬프트는 "문서만 참고하라"는 지시와 "답이 없으면 찾을 수 없다고 답하라"는 지시를 함께 담는다.
- 체인의 딕셔너리 `{"context": retriever | format_docs, "question": RunnablePassthrough()}`는 `chain.invoke(question)`에 넘긴 같은 질문 문자열이 두 갈래로 동시에 들어간다는 뜻이다 — 한쪽은 검색해서 컨텍스트로, 다른 한쪽은 그대로 질문으로.
- 2번 섹션은 체인이 내부적으로 하는 일(검색 → 프롬프트에 주입)을 코드로 그대로 풀어써서, 3번 섹션의 체인이 "마법"이 아니라 이 단계들을 파이프로 묶은 것뿐임을 보여준다.

실행 방법 (examples 디렉터리에서):

```bash
uv run python ch03_rag/03_rag_chain.py
```

## 실제 출력

아래는 저자가 로컬 `flashnext` 모델로 실제 실행해 캡처한 결과다. LLM 응답이므로 여러분의 결과와 글자 단위로 같지 않을 수 있다.

```text
{{#include ../../../outputs/ch03_rag/03_rag_chain.out:2:}}
```

`=== 1 ===`에서 17개 청크(앞 장과 동일한 색인)가 만들어지고, `as_retriever`가 돌려준 retriever의 타입은 `VectorStoreRetriever`다.

`=== 2 ===`는 "재택근무는 일주일에 며칠까지 할 수 있어?" 질문으로 검색한 결과, `03_company_handbook.md`에서 나온 두 조각이 검색됐고, 그 뒤 `--- 모델에게 보낼 프롬프트 ---` 아래 렌더링된 프롬프트 안에 두 조각의 실제 본문 — 재택근무 조각(한 주 최대 2일, 전날 오후 6시까지 신청, 수요일 예외)과 연차 휴가 조각 — 이 그대로 들어가 있는 것을 볼 수 있다. 이 캡처에서는 두 번째로 가까운 조각이 질문과 직접 관련이 없는 연차 휴가 조각이었는데, `k=2`가 "관련 있는 조각만"이 아니라 "가장 가까운 두 개"를 뜻하기 때문이다.

`=== 3 ===`의 체인 타입은 `RunnableSequence`다. 같은 질문을 체인에 넣자 답변은 `한 주에 최대 2일까지 할 수 있습니다.`로, 이번 캡처에서는 검색된 문서의 재택근무 조각 문장을 그대로 근거로 삼아 답했다.

`=== 4 ===`는 문서에 없는 질문("회사 주차 요금은 한 달에 얼마야?")이다. 검색은 여전히 `03_company_handbook.md`의 두 조각(업무 장비, 재택근무)을 돌려줬다 — retriever는 항상 `k`개를 돌려주므로, 관련 없는 질문에도 가장 가까운(하지만 무관한) 조각을 내놓는다. 이번 캡처에서 모델의 답변은 `문서에서 찾을 수 없습니다`로, 프롬프트의 지시를 따라 무관한 조각에서 답을 지어내지 않고 그대로 인정했다.

## 요점 정리

- RAG는 검색된 조각을 프롬프트의 컨텍스트로 주입해, 모델이 학습하지 않은 내용에 대해서도 근거를 갖고 답하게 한다.
- `{"context": retriever | format_docs, "question": RunnablePassthrough()}`는 같은 입력이 검색(컨텍스트)과 그대로 전달(질문)이라는 두 갈래로 동시에 흐르는 `RunnableParallel`이다.
- retriever는 관련성과 무관하게 항상 `k`개를 돌려준다 — "문서에 없으면 찾을 수 없다고 답하라"는 프롬프트 지시가 무관한 검색 결과를 걸러내는 마지막 방어선이다.
- 프롬프트 지시를 넣었다고 해서 근거 없는 답변이 완전히 사라지는 것은 아니며, 실제 출력으로 매번 확인해야 한다.
