# 수동 도구 실행 루프

## 개념: 왜 필요한가

앞 장에서 모델은 도구를 "요청"만 했다. 이번 장은 그 요청을 실제로 실행해서 루프를 완성한다. 각 `tool_call`을 실행하고, 결과를 그 요청을 가리키는 `tool_call_id`가 담긴 `ToolMessage`로 감싸 대화 기록에 이어붙인 다음, 모델을 다시 호출한다 — 모델이 더 이상 도구를 요청하지 않을 때까지 이 과정을 반복한다.

이 루프가 모든 에이전트의 핵심이다. 다음 LangGraph 장은 이 정확히 같은 로직을 그래프로 다시 구현하고, 최종 캡스톤은 이 위에 코딩 에이전트를 쌓는다. 안전장치도 두 가지 포함한다: 도구 실행 중 발생한 예외는 프로그램을 죽이지 않고 메시지로 모델에 돌려줘서 모델이 스스로 복구를 시도할 기회를 주고, `MAX_ITERS`는 진행이 없는 무한 루프를 막는다.

`run_tool_call(tc)`는 세 갈래로 나뉜다: 이름이 도구 목록에 없으면 바로 오류 `ToolMessage`를 만들고, 있으면 `tool.invoke(tc)`처럼 **`tool_call` dict 전체**를 넘겨 프레임워크가 `ToolMessage`를 직접 만들게 하고(`args`만 넘기면 원시 반환값이 오므로 안 된다), 그 호출이 예외를 던지면 `try/except`로 잡아 오류 메시지를 담은 `ToolMessage`로 바꾼다. `run_loop`는 `messages` 리스트를 계속 키우면서, `for ... else` 구문의 `else` 절을 이용해 `MAX_ITERS`번을 다 돌고도 최종 답이 안 나온 경우를 가드한다. `id`는 값 자체를 출력하지 않고 `tool_call_id == tc["id"]` 같은 비교나 존재 여부로만 다룬다 — 매 요청마다 무작위로 바뀌기 때문에 정적 출력 파일에 그대로 적으면 재현 비교가 불가능해진다.

실행 방법 (examples 디렉터리에서):

```bash
uv run python ch02_tools/02_tool_loop.py

```

`=== 1 ===`은 같은 `tool_call`을 두 가지 방식으로 실행한 대조다: 전체 dict를 넘기면 `ToolMessage`(그리고 `tool_call_id`가 요청과 정확히 일치)가 오지만, `args`만 넘기면 순수 문자열이 그대로 온다.

`=== 2 ===`의 루프는 이번 캡처에서 모델을 세 번 호출했다. 1단계에서 `lookup_stock`을 사과·바나나 두 번(병렬로) 호출했고, 2단계에서 그 결과를 받아 `multiply(a=12, b=5)`를 호출했으며, 3단계에서는 더 이상 도구를 요청하지 않고 `최종 답: 사과 재고 12개 × 바나나 재고 5개 = **60**입니다.`로 답했다. 이번 캡처의 모든 tool-call 턴에서 `content`는 비어 있어 위 출력에 `content:` 줄이 보이지 않는다 — 앞 장에서 본 것과 달리 이번에는 모델이 설명 텍스트 없이 바로 도구를 호출했다(프롬프트에 따라 달라질 수 있는 부분이다). `메시지 흐름:` 줄은 `HumanMessage → AIMessage → ToolMessage → ToolMessage → AIMessage → ToolMessage → AIMessage`로, 히스토리가 어떻게 자라났는지 그대로 보여준다.

`=== 3 ===`은 먼저 결정적으로 두 가지 오류를 보여준다: 존재하지 않는 도구 이름(`subtract`)은 `알 수 없는 도구: subtract`로, 존재하지 않는 품목(`수박`)은 `도구 실행 오류: ValueError: 재고 목록에 없는 품목: 수박`으로 돌아온다. 이어서 같은 수박 질문을 모델에게 직접 던진 루프를 보면, 모델은 1단계에서 `lookup_stock(item="수박")`을 호출했고 그 결과로 온 오류 `ToolMessage`를 받은 뒤, 2단계에서 도구를 다시 호출하지 않고 "수박은 현재 창고 재고 목록에 없는 품목입니다"로 스스로 정리해 답했다 — 프로그램이 죽는 대신 모델이 오류 메시지를 이해하고 사용자에게 설명한 것이다.

## 요점 정리

- 도구 실행에는 `tool_call` dict 전체를 넘긴다 — `args`만 넘기면 `ToolMessage`가 아니라 원시 값이 온다.
- 루프는 모델 호출 → `tool_calls` 있으면 실행·`ToolMessage`로 추가 → 없으면 종료, 를 반복한다.
- 도구가 던진 예외는 도구가 아니라 루프가 잡아 `ToolMessage`로 되돌린다 — 프로그램이 죽지 않고 모델이 오류를 보고 스스로 복구를 시도할 수 있다.
- `MAX_ITERS`는 진행이 없는 무한 루프를 막는 안전장치다.
- 이 루프가 다음 LangGraph 장에서 그래프로, 최종적으로 코딩 에이전트로 발전한다.
- 바로 다음 [3부 RAG](../ch03_rag/01_load_split.md)에서는 잠시 도구 루프를 떠나, 검색한 문서를 모델에게 건네 답을 만드는 방법을 다룬다.
