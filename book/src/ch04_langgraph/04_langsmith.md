# LangSmith 트레이싱

## 개념: 왜 필요한가

그래프가 커지면 "왜 이 답이 나왔는가"를 최종 출력만 보고는 알 수 없다 — 어느 노드가 몇 번 돌았는지, 모델이 어떤 인자로 도구를 불렀는지, 토큰을 얼마나 썼는지를 봐야 한다. LangSmith는 그 실행 기록을 트리로 보여주는 서비스다.

다만 트레이스는 클라우드로 전송되므로, 이 책은 기본값을 꺼 두고 켜는 방법만 보여준다. 그리고 이 장의 실제 출력은 LangSmith에 아무것도 보내지 않고 로컬에서 같은 정보를 재구성한 것이다 — 이 책의 원칙(싣는 출력은 전부 실제 실행 결과)을 지키면서, 트레이스가 무엇을 보여주는지는 그대로 설명하기 위해서다. 스크린샷이나 트레이스 링크는 싣지 않는다.

- `tracing_is_enabled()`는 환경변수만 읽고 네트워크를 쓰지 않는다 — 스위치 상태를 확인하는 것 자체는 아무것도 전송하지 않는다.
- `LANGSMITH_TRACING` / `LANGCHAIN_TRACING_V2` 등 네 이름이 모두 인식되고, **키가 없어도 스위치 자체는 켜진다**(실제 전송에는 키가 필요하다) — 이 둘은 서로 다른 문제다.
- 조회 함수(`get_env_var`)에 캐시가 걸려 있어, 환경변수를 바꾼 뒤에는 캐시를 비워야 값이 바뀐다 — 모르면 "켰는데 안 켜진다"로 보인다. 그래서 `tracing_state()`가 매번 `utils.get_env_var.cache_clear()`를 먼저 호출한다.
- `app.stream(..., stream_mode="debug")`가 노드마다 시작/끝 이벤트를 내주며, 그 이벤트의 `name`은 `add_node`에 준 이름과 같다.
- 이벤트에 들어 있는 식별자(`payload["id"]`)와 시각(`event["timestamp"]`)은 실행마다 달라져 재현 가능한 출력이 아니므로 찍지 않는다.

```bash
uv run python ch04_langgraph/05_langsmith_trace.py
```

`=== 1 ===`에서 스위치가 `False` → `True` → `False`로 바뀌는 것을 볼 수 있다: 아무 설정이 없을 때는 꺼짐, `LANGSMITH_TRACING=true`를 주면 (API 키 없이도) 켜짐, 다시 지우면 꺼짐이다. 이 구간은 `tracing_is_enabled()` 호출만 반복했을 뿐 어떤 네트워크 요청도 만들지 않았다.

`=== 2 ===`의 이벤트 순서는 `model → tools → model → tools → model`로, 2부 2장·4부 1장에서 본 것과 정확히 같은 루프다. 1단계에서 모델이 `lookup_stock({"item": "사과"})`와 `lookup_stock({"item": "바나나"})`를 요청했고(입력 450 / 출력 55 / 합계 505 토큰), 2단계에서 도구가 각각 `사과 재고: 12개`, `바나나 재고: 5개`를 돌려줬다. 3단계에서 모델이 `multiply({"a": 12, "b": 5})`를 요청했고(입력 545 / 출력 37 / 합계 582 토큰), 4단계에서 도구가 `60`을 돌려줬다. 5단계에서 모델이 더 이상 도구를 부르지 않고 `사과 재고 12개 × 바나나 재고 5개 = **60**입니다.`로 답했다(입력 601 / 출력 25 / 합계 626 토큰).

`=== 3 ===`은 트레이스 트리의 이름이 그래프 노드 이름과 정확히 대응한다는 증거다: 그래프에 등록한 노드는 `['model', 'tools']`이고, 트레이스에서 관찰된 순서는 `model → tools → model → tools → model`이며, 관찰된 이름이 모두 등록된 노드에 포함되는지를 검사한 결과는 `True`다. LangSmith UI에서 보는 트레이스 트리의 각 박스 이름도 바로 이 `add_node`에 준 이름이다.

`=== 4 ===`는 이 실행 전체의 토큰 사용량 합계다: 모델 호출 3회, 입력 토큰 합계 1596 / 출력 토큰 합계 117 / 전체 합계 1713. 지연시간은 이 책의 캡처에는 넣지 않는다고 명시했는데, 실행마다 달라져 재현 가능한 값이 아니기 때문이다.

공식 문서에 따르면 LangSmith UI는 이 캡처가 보여준 것과 같은 트리를 웹에서 접고 펼 수 있는 형태로 보여주고, 각 run 옆에 실제 소요 시간(지연시간)이 함께 표시되며, 여러 실행을 나란히 비교할 수 있다. 이 책은 그 화면을 캡처해 싣지 않는다 — 위 텍스트 출력이 이 장에서 재현하는 실제 결과의 전부다.

## 요점 정리

- `tracing_is_enabled()`는 환경변수만 읽고 네트워크에 접속하지 않는다 — 스위치를 확인하는 것 자체는 아무것도 전송하지 않는다.
- API 키가 없어도 스위치 자체는 켜진다. 실제 전송에는 별도로 키가 필요하다.
- 조회 함수에 캐시가 걸려 있으므로, 코드 안에서 환경변수를 바꾼 뒤에는 캐시를 비워야 한다.
- `stream_mode="debug"`가 내주는 이벤트의 `name`은 `add_node`에 준 이름과 같다 — 트레이스 트리의 이름과 그래프 노드 이름은 1:1로 대응한다.
- LangSmith UI는 이 장이 로컬로 재구성한 것과 같은 트리를, 접고 펼 수 있는 형태로, 소요 시간과 함께 보여준다.
