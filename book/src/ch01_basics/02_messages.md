# 메시지와 멀티턴 대화

## 개념: 왜 필요한가

LangChain은 대화를 세 가지 역할의 메시지로 표현한다. `SystemMessage`는 모델의 태도나 규칙을 정하고, `HumanMessage`는 사용자의 발화, `AIMessage`는 모델의 응답이다. `model.invoke()`에 문자열 하나 대신 메시지 리스트를 넘기면 그 리스트 전체가 하나의 대화 문맥이 된다.

여기서 중요한 사실은 LLM 자체는 상태를 저장하지 않는다(stateless)는 점이다. 서버는 이전에 어떤 대화를 나눴는지 기억하지 못한다. "대화가 이어지는 것처럼" 보이는 이유는, 애플리케이션이 매 호출마다 지금까지의 메시지 리스트 전체를 다시 보내기 때문이다. 즉 대화 기록 리스트 자체가 곧 모델의 기억이다.

이 구조를 이해하면 두 가지가 명확해진다. 첫째, 기록을 넘기지 않으면 모델은 방금 전 대화조차 알지 못한다. 둘째, `AIMessage`는 모델이 반환한 객체일 필요가 없다 — 개발자가 직접 만들어 넣어도 모델은 그것을 "자신이 이전에 한 말"로 취급한다. 뒤에 나올 LangGraph의 체크포인터는 이 리스트를 자동으로 저장하고 불러오는 역할을 한다.

## 요점 정리

- 대화는 `SystemMessage`/`HumanMessage`/`AIMessage` 리스트로 표현한다.
- 모델은 상태를 저장하지 않는다. 앱이 매번 전체 기록을 다시 보내야 이전 대화를 "기억하는" 것처럼 동작한다.
- 기록에 무엇을 넣느냐가 곧 모델이 아는 전부다 — 기록이 없으면 방금 전 대화도 모른다.
- `AIMessage`는 모델이 반환한 것이 아니어도 기록에 넣을 수 있다. 역할은 데이터일 뿐이다.
- 나중에 LangGraph의 체크포인터가 이 기록 관리를 자동화한다.
