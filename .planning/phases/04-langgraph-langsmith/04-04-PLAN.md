Facts already confirmed during planning (verified live — do not re-derive). **Two of these correct errors in 04-RESEARCH.md; trust this section over the research document:**
- `langsmith.utils.tracing_is_enabled()` checks only `LANGSMITH_TRACING_V2` / `LANGCHAIN_TRACING_V2`, falling back to `LANGSMITH_TRACING` / `LANGCHAIN_TRACING`, and compares the value to the string `"true"`. **It does NOT require an API key** — `LANGSMITH_TRACING=true` alone returns `True` (research claimed a key was needed; it is not). It makes no network call.
- **`langsmith.utils.get_env_var` is `@functools.lru_cache`-decorated.** Flipping `os.environ` after the first call has no effect — the research document's in-process toggle snippet silently prints `False` forever. To show the switch in one process you must call `utils.get_env_var.cache_clear()` after each change. Verified: default `False` → set + `cache_clear()` → `True` → unset + `cache_clear()` → `False`.
- `stream_mode="debug"` yields events with keys `type`, `payload`, `step`, `timestamp`. `payload` has `id`, `input`, `name`, `triggers` for `type == "task"`, and `id`, `name`, `result`, `error`, `interrupts` for `type == "task_result"`. `payload["result"]` is a **dict** with a single key `messages` (research's tuple-list assumption was wrong). `payload["name"]` equals the registered node name.
- For the baseline question the event sequence is: `task/task_result model` (step 1), `task/task_result tools` (step 2), `model` (3), `tools` (4), `model` (5). `AIMessage.usage_metadata` is populated on every model step (e.g. `{'input_tokens': 450, 'output_tokens': 55, 'total_tokens': 505, ...}`); `ToolMessage` carries `name`, `status` and `content`.
- `payload["id"]` is a UUID and `event["timestamp"]` is a timestamp — never print either. `event["step"]` is a small deterministic integer and is safe to print.
- `scripts/masking.py` already lists `LANGSMITH_API_KEY` in `SECRET_ENV_VARS`, and `test_masking.py` already covers it. Do not modify either file.
- `book/src/ch01_basics/01_chat_model.md` includes the **whole** `examples/.env.example`, so new lines there appear in 1부 1장 and need one explanatory sentence (the same thing Phase 3 did for `EMBEDDING_*`).
